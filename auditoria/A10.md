# A10 — Cobertura de teste e o que o teste não pega

## Resumo

A suíte confirma os números que a documentação anuncia: 74 blocos `test_that`, 154
expectativas, 6 arquivos, zero falhas. O que ela não faz é cobrir o pipeline.
Por teste de mutação (substituição de cada função por `function(...) NULL`),
**26 das 62 funções `mape_*` podem ser apagadas sem que uma única expectativa
falhe** — entre elas `mape_escrever_tabela()`, `mape_montar_base_larga()`,
`mape_paridade()`, `mape_consolidar_dimensao()` e `mape_deflacionar()`, isto é,
todo o caminho de escrita, a montagem da base larga, o teste de paridade e o
mecanismo que existe para impedir o defeito nº 1 do legado. Nove achados. O mais
grave (A10-03) é que a garantia que o `CLAUDE.md` dá sobre `mape_montar_base_larga()`
é falsa: ela nomeia só `06_financas`, ignora as 54 chaves duplicadas de
`15_dados_historicos` e **exclui essa dimensão inteira da base larga em silêncio** —
423 colunas, não 440. Nenhum teste cobre a função, então nada disso aparece.

## Achados

### A10-01 · MÉDIO · a suíte de testes reescreve um artefato versionado a cada execução

**Afirmação:** rodar `testthat::test_dir("tests/testthat")` modifica
`qa/00_diretorios__municipios.md`, que é rastreado pelo git, e não há como
desligar isso: `mape_validar_tabela()` chama `mape_gravar_relatorio_qa()`
incondicionalmente (`R/validacao.R:168`), sem argumento de controle.

**Reprodução:**
```r
# a partir da raiz do repositório
system("git checkout -- qa/00_diretorios__municipios.md")
cat("antes:\n"); system("git status --short qa/")
invisible(testthat::test_dir("tests/testthat", reporter = "silent"))
cat("depois:\n"); system("git status --short qa/")
system("git diff qa/00_diretorios__municipios.md")
system("git checkout -- qa/00_diretorios__municipios.md")   # restaure
```

**Saída observada:**
```
antes:
depois:
 M qa/00_diretorios__municipios.md
diff --git a/qa/00_diretorios__municipios.md b/qa/00_diretorios__municipios.md
index 46d48bd..b05f6e6 100644
--- a/qa/00_diretorios__municipios.md
+++ b/qa/00_diretorios__municipios.md
@@ -1,6 +1,6 @@
 # QA — 00_diretorios/municipios
 
-Gerado em 2026-07-26 09:40:23.
+Gerado em 2026-07-26 10:54:09.
```

Efeito colateral secundário observado nesta máquina: a pasta do projeto está sob
um serviço de sincronização, e a reescrita seguida do `git checkout --` produziu
um arquivo de conflito `qa/00_diretorios__municipios 2.md` (324 bytes, carimbo
`10:54:09`, idêntico à versão gerada pela suíte). Ou seja: a suíte não só suja a
árvore, como pode deixar lixo que o `git checkout` não remove, porque não é
rastreado.

**Impacto:** a suíte não é hermética. Quem roda os testes antes de commitar
recebe a árvore suja e ou commita um carimbo de data sem sentido, ou faz
`git checkout` — e nesse caso o `qa/*.md` versionado deixa de corresponder à
última execução da validação. Também impede rodar a suíte em CI com
`git diff --exit-code` como guarda.

**Tentativa de refutação:** procurei um argumento de desligamento em
`mape_validar_tabela()` (`R/validacao.R:21-22`: `x, tabela, chaves, diretorio,
erro` — não existe) e verifiquei se o teste que dispara a gravação
(`tests/testthat/test-io-dicionario-validacao.R:146-151`) poderia ser o único
responsável: não é, o bloco `"a tabela do diretório passa nas doze checagens"`
(linha 108) já grava. Também confirmei que o arquivo é versionado
(`git ls-files --error-unmatch` devolve 0), então não é lixo ignorado.

**Correção sugerida:** acrescentar `gravar = TRUE` à assinatura de
`mape_validar_tabela()` e envolver a linha 168 em `if (gravar)`; os testes passam
`gravar = FALSE`. Alternativamente, `mape_gravar_relatorio_qa()` só reescreve se
o conteúdo mudou de fato (comparar tudo menos a linha do carimbo), o que também
resolve o ruído de `git status` no uso normal.

### A10-02 · ALTO · 26 das 62 funções `mape_*` podem virar `NULL` sem quebrar nenhum teste

**Afirmação:** substituindo qualquer uma de 26 funções de `R/` por
`function(...) NULL`, as 154 expectativas continuam passando. Entre elas estão
`mape_escrever_tabela()` (todo o caminho de publicação), `mape_montar_base_larga()`,
`mape_consolidar_dimensao()`, `mape_paridade()`, `mape_esqueleto_painel()`,
`mape_deflacionar()`, `mape_aplicar_tipos()` e `mape_aplicar_renomeacao()`.

**Reprodução:**
```r
# a partir da raiz do repositório
suppressMessages(library(testthat))

rodar <- function(mutacao = NULL) {
  for (f in list.files("R", pattern = "[.]R$", full.names = TRUE))
    source(f, local = FALSE, encoding = "UTF-8")
  # neutraliza a gravação em qa/ para não sujar a árvore (ver A10-01)
  assign("mape_gravar_relatorio_qa", function(...) invisible(NULL), envir = globalenv())
  assign("diretorio_teste", data.frame(
    id_municipio   = c("1100015", "3304557", "3550308", "1700400"),
    id_municipio_6 = c("110001",  "330455",  "355030",  "170040"),
    nome_municipio = c("Alta Floresta D'Oeste", "Rio de Janeiro",
                       "São Paulo", "Abreulândia"),
    stringsAsFactors = FALSE), envir = globalenv())
  if (!is.null(mutacao)) mutacao()
  rep <- ListReporter$new()
  with_reporter(rep, for (a in list.files("tests/testthat", "^test-.*[.]R$", full.names = TRUE)) {
    rep$start_file(basename(a))
    suppressMessages(source(a, local = FALSE, encoding = "UTF-8"))
    rep$end_file()
  })
  res <- rep$get_results(); nf <- 0
  for (t in res) for (e in t$results)
    if (inherits(e, "expectation_failure") || inherits(e, "expectation_error")) nf <- nf + 1
  nf
}

cat("baseline falhas:", rodar(), "\n")
for (fn in c("mape_escrever_tabela", "mape_montar_base_larga", "mape_paridade",
             "mape_consolidar_dimensao", "mape_deflacionar", "mape_esqueleto_painel",
             "mape_aplicar_tipos", "mape_recalcular_campos", "mape_sha256")) {
  n <- rodar(local({ nm <- fn; function() assign(nm, function(...) NULL, envir = globalenv()) }))
  cat(sprintf("NO-OP %-26s falhas=%d\n", fn, n))
}
```

**Saída observada:**

O sweep completo sobre as 62 funções (na íntegra na seção Cobertura) devolve
26 sobreviventes. Grupos, por risco:

| grupo | funções sem cobertura |
|---|---|
| escrita e publicação | `mape_escrever_tabela`, `mape_gravar_relatorio_qa`, `mape_registrar_tabela`, `mape_atribuir_variaveis`, `mape_registrar_pendencia`, `mape_versionavel` |
| derivação central | `mape_consolidar_dimensao`, `mape_montar_base_larga`, `mape_esqueleto_painel`, `mape_aplicar_tipos`, `mape_aplicar_renomeacao`, `mape_recalcular_campos`, `mape_gerar_documentacao_completa`, `mape_fontes_de` |
| dinheiro | `mape_deflacionar`, `mape_marcar_nominal` |
| auditoria e migração | `mape_paridade`, `mape_migrar_do_legado`, `mape_sincronizar_tipos`, `mape_registrar_dimensao_legado` |
| proveniência | `mape_sha256`, `mape_verificar_raw`, `mape_registrar_manifesto`, `mape_registrar_proveniencia` |
| BigQuery (aceitável) | `mape_query`, `mape_billing_id` |

**Impacto:** a suíte prova o comportamento das funções *utilitárias*
(`mape_como_codigo`, `mape_join`, `mape_compactar_painel`, `mape_derivadas`) e
nada do *pipeline*. Uma regressão em `mape_escrever_tabela()` — por exemplo,
voltar a chamar `write.csv` sem `row.names = FALSE`, que é o defeito que o
próprio comentário de `R/io.R:54` diz combater — passa verde. O mesmo vale para
`mape_paridade()`, sobre a qual o projeto apoia a afirmação "zero diferenças não
explicadas": se ela comparasse zero colunas, o `.md` diria "Nenhuma diferença" e
nenhum teste reclamaria.

**Tentativa de refutação:** (a) `mape_query`/`mape_billing_id` tocam o BigQuery e
não deveriam ter teste mesmo — aceito, e por isso as separei; sobram 24.
(b) Cobertura indireta: o sweep já mede isso, porque um no-op quebra qualquer
chamador testado. Duas funções sem chamada direta em teste **morrem** no sweep
(`mape_mb`, `mape_tabelas_publicadas`) e por isso *não* estão na lista.
(c) `mape_recalcular_campos` tem chamada direta em
`tests/testthat/test-documentacao-ingestao.R:9` e mesmo assim sobrevive — o
motivo está em A10-06. (d) `mape_gravar_relatorio_qa` é neutralizada pelo próprio
harness; verifiquei separadamente que o único teste que a menciona é vacuário
(A10-06), então a classificação se sustenta.

**Correção sugerida:** priorizar, nesta ordem, testes para
`mape_escrever_tabela()` (bloqueio por validação, `row.names`, equivalência
Parquet↔csv.gz), `mape_montar_base_larga()` (A10-03), `mape_paridade()` (fixture
de referência mínima, com uma coluna que difere de propósito, para provar que a
comparação é célula a célula) e `mape_deflacionar()` (A10-07). Para
`mape_escrever_tabela()` o teste é **impossível de escrever hoje** sem gravar em
`dados/`, porque `mape_caminho()` é `here::here()` puro e não aceita raiz
injetada — ver A10-05; o pré-requisito é dar a `mape_caminho()` uma raiz
configurável.

### A10-03 · ALTO · a garantia do `CLAUDE.md` sobre `mape_montar_base_larga()` é falsa, e não há teste que a verifique

**Afirmação:** o `CLAUDE.md` diz, sobre as duas tabelas com chave duplicada
(`06_financas`, 222; `15_dados_historicos`, 54): *"Mantidas de propósito, para o
problema ficar visível. `mape_montar_base_larga()` se recusa a rodar e nomeia a
responsável."* Na prática a função nomeia **só `06_financas`**, porque a guarda
(`R/dimensao.R:101-110`) pula toda dimensão sem coluna `ano` (`if (!"ano" %in%
names(parte)) next`) — e `15_dados_historicos` não tem `ano`. Pior: o mesmo
`next` no laço de junção (`R/dimensao.R:122`) faz a dimensão inteira ser
**excluída da base larga sem mensagem nenhuma**. A base sai com 423 colunas.
Nenhuma expectativa cobre a função (A10-02).

**Reprodução:**
```r
for (f in list.files("R", pattern = "[.]R$", full.names = TRUE)) source(f, encoding = "UTF-8")

cat("--- 15_dados_historicos: tem `ano`? tem chave duplicada? ---\n")
h <- mape_ler_tabela("15_dados_historicos", camada = "dimensao")
cat("coluna `ano` presente:", "ano" %in% names(h), "\n")
cat("linhas:", nrow(h), " id_municipio distintos:", length(unique(h$id_municipio)),
    " -> duplicadas:", nrow(h) - length(unique(h$id_municipio)), "\n")

cat("\n--- quem a guarda nomeia ---\n")
cat(tryCatch(mape_montar_base_larga(), error = function(e) conditionMessage(e)), "\n")

cat("\n--- a dimensao entra na base larga? ---\n")
b <- suppressMessages(mape_montar_base_larga(deduplicar = TRUE))
cat("colunas da base larga:", ncol(b), "\n")
cat("alguma coluna de 15_dados_historicos entrou:",
    any(setdiff(names(h), c("id_municipio", "ano")) %in% names(b)), "\n")
```

**Saída observada:**
```
--- 15_dados_historicos: tem `ano`? tem chave duplicada? ---
coluna `ano` presente: FALSE 
linhas: 5646  id_municipio distintos: 5592  -> duplicadas: 54 

--- quem a guarda nomeia ---
Não dá para montar a base larga: há dimensão com chave duplicada.
  - 06_financas (222 chaves duplicadas, 235 linhas excedentes)

Juntar assim multiplicaria linhas, que é o defeito do legado. Resolva na origem, ou passe deduplicar = TRUE para aceitar a primeira ocorrência de cada chave — o que é uma escolha arbitrária e fica registrada no relatório.

--- a dimensao entra na base larga? ---
colunas da base larga: 423 
alguma coluna de 15_dados_historicos entrou: FALSE 
```

**Impacto:** três coisas de uma vez. (1) A mitigação anunciada cobre metade dos
casos: quem lê o `CLAUDE.md` conclui que as 54 chaves duplicadas de
`15_dados_historicos` estão sob vigilância, e não estão. (2) Uma dimensão
publicada inteira — 8 variáveis, os dados históricos de 1920 — **não existe na
base larga** e nada avisa; quem monta a base e não acha `receita_tributaria_1920_norm_idx`
não tem como saber se a coluna foi removida, renomeada ou perdida numa junção.
(3) O número "440 colunas" da documentação não fecha com as 423 medidas (a
divergência em si é de A9; aqui interessa que a causa mecânica é este `next`
silencioso, e que nenhum teste a exporia).

**Tentativa de refutação:** (a) *"Talvez seja intencional: tabela transversal não
entra em painel."* Pode ser a intenção — mas então o `CLAUDE.md` não deveria
prometer que a função "nomeia a responsável" para as duas tabelas, e a exclusão
deveria produzir mensagem. `mape_consolidar_dimensao()`, na mesma camada,
**avisa** quando descarta fonte sem `ano` (`R/dimensao.R:41-44`);
`mape_montar_base_larga()` não avisa. A assimetria entre as duas funções da mesma
camada é o argumento mais forte de que é descuido, não desenho. (b) *"Talvez
`15_dados_historicos` não tenha mesmo 54 duplicadas."* Medi: 5.646 linhas, 5.592
`id_municipio` distintos, 54 excedentes — bate exatamente com o número declarado.
(c) *"Talvez o teste `mape_juntar recusa tabela sem ano` já cubra isso."*
(`test-consumo.R:54-59`) — não: ele testa `mape_juntar()`, função diferente, que
*erra* nesse caso; `mape_montar_base_larga()` pula em silêncio.

**Correção sugerida:** em `R/dimensao.R`, trocar os dois `next` por um caminho
explícito: (1) na guarda, checar unicidade pela chave declarada no dicionário
(`id_municipio` sozinho quando não há `ano`), de modo que `15_dados_historicos`
apareça na lista; (2) no laço de junção, emitir
`message("[", d, "] fora da base larga: não tem coluna `ano`")` e devolver a
lista de dimensões excluídas como atributo do resultado. Teste de regressão em
"Testes propostos", R5 e R5b.

### A10-04 · MÉDIO · a suíte valida 1 das 26 tabelas publicadas e lê 6

**Afirmação:** instrumentando `mape_ler_tabela()` durante a suíte inteira, só 6
tabelas publicadas são lidas (`00_diretorios/municipios`, `02_populacao`,
`06_financas`, `13_seguranca`, `14_corrupcao`, `15_dados_historicos`), e
`mape_validar_tabela()` roda sobre **uma só** (`00_diretorios/municipios`).
As outras 25 nunca passam pelas doze checagens em nenhum teste — e 23 delas
também não têm alvo no grafo do `targets`.

**Reprodução:**
```r
suppressMessages(library(testthat))
for (f in list.files("R", pattern = "[.]R$", full.names = TRUE)) source(f, encoding = "UTF-8")
assign("mape_gravar_relatorio_qa", function(...) invisible(NULL), envir = globalenv())
assign("diretorio_teste", data.frame(
  id_municipio   = c("1100015", "3304557", "3550308", "1700400"),
  id_municipio_6 = c("110001",  "330455",  "355030",  "170040"),
  nome_municipio = c("a", "b", "c", "d"), stringsAsFactors = FALSE), envir = globalenv())

reg <- new.env(); reg$lidas <- character(); reg$validadas <- character()
local({
  o1 <- mape_ler_tabela;    assign("mape_ler_tabela",
    function(tabela, ...) { reg$lidas <- c(reg$lidas, tabela); o1(tabela, ...) }, envir = globalenv())
  o2 <- mape_validar_tabela; assign("mape_validar_tabela",
    function(x, tabela, ...) { reg$validadas <- c(reg$validadas, tabela); o2(x, tabela, ...) }, envir = globalenv())
})
rep <- ListReporter$new()
with_reporter(rep, for (a in list.files("tests/testthat", "^test-.*[.]R$", full.names = TRUE)) {
  rep$start_file(basename(a)); suppressMessages(source(a, local = FALSE, encoding = "UTF-8")); rep$end_file()
})
cat("tabelas lidas:\n");   print(table(reg$lidas))
cat("tabelas validadas:\n"); print(table(reg$validadas))
cat("total publicado: 26\n")
```

**Saída observada:**
```

                      12                        8                        4 
             06_financas             13_seguranca      15_dados_historicos 
                       1                        1                        1
```

(`99_inexistente/nada` é a sonda do teste de mensagem de erro.) Contagem estática
complementar: 17 dos 74 blocos, com 36 das 152 expectativas (24%), dependem de
Parquet publicado no disco; os outros 76% rodam sobre dado sintético.

**Impacto:** o `CLAUDE.md` diz "154 expectativas" ao lado de "26 tabelas
publicadas" e a leitura natural é que uma coisa cobre a outra. Não cobre. Como as
23 tabelas fora do grafo também nunca são validadas por `tar_make()`, existe um
conjunto de tabelas publicadas — a maioria — sobre as quais **nenhum mecanismo
automático do repositório passa**, nem teste nem pipeline. Uma corrupção de
Parquet, uma coluna que muda de tipo, um `id_municipio` que perde o zero: nada
disso é detectado por rodar a suíte.

**Tentativa de refutação:** (a) *"Os `qa/*.md` cobrem as 26."* Cobrem, mas foram
gerados uma vez, por script de migração, e não são reexecutados por nada que o
usuário rode no dia a dia — a suíte regenera exatamente um deles (A10-01). (b)
