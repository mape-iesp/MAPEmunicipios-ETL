## Achados

### A5-01 · ALTO · `mape_ler(painel = TRUE)` falha em toda tabela que declara regra de preenchimento temporal

**Afirmação:** `mape_ler(tabela, painel = TRUE)` termina com o erro
`replacement has 0 rows` em **todas** as tabelas cujo
`regra_preenchimento_temporal` não é `"nenhuma"` — que são exatamente as únicas
em que o parâmetro faz alguma coisa. A causa está em `R/painel.R:82-86`: o
`merge()` recebe um `x` que já tem coluna `ano` e um `mapa` que também tem, e o
dplyr/base renomeia as duas para `ano.x` e `ano.y`; a linha seguinte referencia
`expandido$ano`, que passa a ser `NULL`.

**Reprodução:**
```r
suppressWarnings(suppressMessages({
  for (f in list.files("R", pattern = "[.]R$", full.names = TRUE)) source(f, encoding = "UTF-8")
}))

for (t in c("03_meio_ambiente/adaptabrasil", "09_educacao/ideb",
            "11_transportes/tarifa_zero")) {
  cat("=====", t, "=====\n")
  r <- tryCatch(mape_ler(t, painel = TRUE),
                error = function(e) paste("ERRO:", conditionMessage(e)))
  if (is.character(r)) cat(r, "\n") else cat("ok:", nrow(r), "linhas\n")
}

# causa raiz, isolada:
y <- data.frame(id_municipio = c("1100015", "1100023"), ano = c(2015L, 2015L),
                v = c(1, 2), stringsAsFactors = FALSE)
y$ano_ref <- y$ano                       # é o que mape_ler() faz em consumo.R:47
mapa <- expand.grid(ano_ref = 2015L, ano = 2014:2016)
cat("\nnomes depois do merge interno de mape_expandir_painel():\n")
print(names(merge(y, mapa, by = "ano_ref")))
```

**Saída observada:**
```
===== 03_meio_ambiente/adaptabrasil =====
ERRO: replacement has 0 rows, data has 200520 
===== 09_educacao/ideb =====
ERRO: replacement has 0 rows, data has 111388 
===== 11_transportes/tarifa_zero =====
ERRO: replacement has 0 rows, data has 578 

nomes depois do merge interno de mape_expandir_painel():
[1] "ano_ref"      "id_municipio" "ano.x"        "v"            "ano.y"
```

**Impacto:** `painel = TRUE` é o único caminho que a interface de consumo oferece
para ir da camada fonte (o dado "como observado") ao painel município × ano, e é
o mecanismo que sustenta a decisão central do projeto — guardar o observado e
expandir sob demanda. Ele está inoperante desde sempre. Quem consome uma das
sete fontes fatiadas e quiser a série tem de reimplementar a expansão à mão, ou
voltar a ler a dimensão — que é o que a arquitetura queria evitar. O parâmetro
está documentado em `R/consumo.R:21-24`, na roxygen, e nos `README.md` gerados
de cada fonte.

**Tentativa de refutação:** (a) Testei se o erro vinha de dado sujo em uma tabela
específica: reproduz nas três, com contagens de linha diferentes, e reproduz em
um data frame sintético de 2 linhas. (b) Verifiquei se `mape_expandir_painel()`
está simplesmente sendo chamada errada por `mape_ler()` e funciona sozinha: ela
funciona quando `x` **não** tem coluna `ano` (é assim que os testes em
`tests/testthat/test-sentinelas-joins-painel.R:95-120` a exercitam), e é
`mape_ler()` que garante que `x` sempre terá — porque só entra no ramo quando
`"ano" %in% names(x)` (`consumo.R:46`). Ou seja, a condição de guarda de
`mape_ler()` garante exatamente a condição que quebra `mape_expandir_painel()`.
(c) Conferi se algum teste cobre: nenhum dos 6 arquivos chama `mape_ler()` com
`painel = TRUE`.

**Correção sugerida:** em `R/painel.R:82`, remover de `x` a coluna de destino
antes do merge, ou nomear a coluna do mapa de forma inequívoca:
```r
if ("ano" %in% names(x) && !identical(de, "ano")) x[["ano"]] <- NULL
expandido <- merge(x, mapa, by = de, all.x = FALSE, all.y = FALSE)
```
e acrescentar `stopifnot(!anyDuplicated(paste(expandido$id_municipio, expandido$ano)))`
depois da expansão (ver A5-08).

### A5-02 · ALTO · `mape_tratar_sentinelas()` converte `id_municipio` de texto para `double`, e o *scaffold* oficial faz isso em toda fonte nova

**Afirmação:** `mape_tratar_sentinelas(x)` com os argumentos padrão
(`cols = NULL`, `converter_numerico = TRUE`) percorre **todas** as colunas,
inclusive as de chave, e converte `id_municipio` de `character` para `double`.
O modelo de `tratar_*.R` que `mape_nova_fonte()` grava (`R/ingestao.R:225-226`)
chama `mape_normalizar_chaves(x)` e, na linha imediatamente seguinte,
`mape_tratar_sentinelas(x)` — desfazendo o contrato que acabou de aplicar.
Nem `mape_validar_schema()` nem `mape_validar_tabela()` detectam, porque
`id_municipio` só tem linha no dicionário sob `00_diretorios/municipios` e `ano`
só sob `02_populacao`.

**Reprodução:**
```r
suppressWarnings(suppressMessages({
  for (f in list.files("R", pattern = "[.]R$", full.names = TRUE)) source(f, encoding = "UTF-8")
}))

fonte <- "01_assistencia_social_dh/cadunico"
x <- mape_ler_tabela(fonte, camada = "fonte")
cat("tipo original de id_municipio:", class(x$id_municipio), "\n")

y <- mape_tratar_sentinelas(x)   # exatamente a linha do scaffold de mape_nova_fonte()
cat("tipo depois de mape_tratar_sentinelas:", class(y$id_municipio), "\n")

cat("\nmape_validar_schema detecta? ->\n")
print(suppressWarnings(mape_validar_schema(y, fonte, erro = FALSE)))

cat("\nmape_validar_dominio_chave detecta? ->\n")
d <- suppressWarnings(mape_validar_dominio_chave(y))
cat("codigos orfaos:", d$n_codigos_orfaos, " linhas orfas:", d$n_linhas_orfas, "\n")

cat("\nonde a chave esta declarada no dicionario:\n")
v <- mape_dicionario("variaveis")
print(v[v$nome_canonico %in% c("id_municipio", "ano"), c("nome_canonico", "tabela", "tipo")])
```

**Saída observada:**
```
tipo original de id_municipio: character 
tipo depois de mape_tratar_sentinelas: numeric 

mape_validar_schema detecta? ->
                             tabela gravidade
1 01_assistencia_social_dh/cadunico     aviso
                                                 coluna
1 cadun_taxa_atualizacao_cadastral_rfpc_ate_meio_sm_pct
                                                        descricao

mape_validar_dominio_chave detecta? ->
codigos orfaos: 0  linhas orfas: 0 

onde a chave esta declarada no dicionario:
   nome_canonico                   tabela      tipo

27           ano             02_populacao   integer
```

**Impacto:** duplo.

1. **O *scaffold* é o defeito.** `mape_nova_fonte()` é o caminho de menor
   resistência que o projeto oferece a "quem chega sem contexto" (é o objetivo (c)
   declarado). O `tratar_*.R` que ele gera publica `id_municipio` como `double`,
   violando o contrato central ("`id_municipio` é texto de 7 dígitos. Código não é
   quantidade"). A validação não avisa. O erro só apareceria no primeiro
   `mape_join()` contra outra tabela, com a mensagem `tipo incompatível na chave`
   — em outro script, dias depois.
2. **A lacuna do dicionário é maior que este caso.** Como `id_municipio` e `ano`
   só existem no dicionário sob uma tabela cada, a checagem de tipo de
   `mape_validar_schema()` **nunca** examina o tipo das chaves em 24 das 26
   tabelas publicadas. É a única coluna do contrato que a validação de tipo não
   cobre.

Riscos correlatos da mesma função, confirmados em teste sintético mas **latentes**
no dado publicado: `mape_tratar_sentinelas()` converte `"1,234"` (separador de
milhar) em `1.234`, um erro de 1000×; e aplica `-999/-9999/-99999 → NA` a toda
coluna numérica sem exceção, o que apagaria um saldo ou uma altitude legítimos.

**Tentativa de refutação:** (a) Testei se a validação salvaria: não — rodei
`mape_validar_schema()` sobre a tabela corrompida e o único problema reportado é
um aviso de domínio pré-existente, sem relação. (b) Testei se
`mape_validar_dominio_chave()` pegaria pela via dos órfãos: não, porque
`setdiff()` coage o `double` a texto e `as.character(1100015) == "1100015"`,
então os códigos continuam casando. (c) Verifiquei se o *scaffold* passa `cols`:
não passa (`R/ingestao.R:226` é literalmente `x <- mape_tratar_sentinelas(x)`).
(d) Verifiquei se algum teste cobre a interação chave × sentinela: os quatro
testes de `mape_tratar_sentinelas()` usam data frames sem coluna de chave. (e) Uma
leitura em que isso é intencional: `converter_numerico` recupera o tipo de
`indice_risco_inundacoes_enxurradas` — mas isso não exige varrer as chaves.

**Correção sugerida:** excluir as colunas de chave por padrão dentro de
`mape_tratar_sentinelas()`:
```r
alvos <- if (is.null(cols)) setdiff(names(x), c("id_municipio", "id_municipio_6", "ano"))
         else intersect(cols, names(x))
```
E, independentemente, registrar `id_municipio` e `ano` em `dicionario/variaveis.csv`
para todas as tabelas, ou fazer `mape_validar_schema()` conferir o tipo das chaves
a partir de `config/parametros.yml:chaves` (que já declara `tipo: character` /
`tipo: integer` e hoje não é lido por ninguém).

### A5-03 · ALTO · `mape_cobertura()` conta coluna de *zero-fill* como dado e reporta 100% onde a cobertura real é de 27 municípios

**Afirmação:** `mape_cobertura("11_transportes")` devolve 5.570 municípios e
100,0% de cobertura para cada ano de 1991 a 2023. A cobertura substantiva da
tabela é de **27 municípios**, em 2005–2017. A diferença inteira vem de
`flag_adota_tarifa_zero`, que é não-nula em 100% das 183.814 linhas (é o
preenchimento com zero) e que `mape_cobertura()` trata como coluna de dado
(`R/consumo.R:312-317`).

**Reprodução:**
```r
suppressWarnings(suppressMessages({

cob <- suppressMessages(mape_cobertura("11_transportes"))
print(head(cob, 3)); cat("...\n"); print(tail(cob, 3))

x <- mape_ler_tabela("11_transportes", camada = "dimensao")
aux <- grep("^(flag_|ano_ref_)", names(x), value = TRUE)
for (a in aux) cat(a, ": pct nao-NA =", round(100 * mean(!is.na(x[[a]])), 2), "%\n")

reais <- setdiff(names(x), c("id_municipio", "ano", aux))
cat("\ncolunas substantivas:", paste(reais, collapse = ", "), "\n")
cat("municipios com valor substantivo, por ano:\n")
print(table(x$ano[rowSums(!is.na(x[, reais, drop = FALSE])) > 0]))
```

**Impacto:** `mape_cobertura()` é anunciada no `CLAUDE.md` e no `README` como
"cobertura real, por ano", e a roxygen (`R/consumo.R:285-288`) afirma
explicitamente que a diferença dela para as colunas `dimensao_*` do legado é que
"aquelas colunas ... diziam 'esta dimensão foi juntada', não 'esta dimensão tem
dado aqui'. Esta função conta presença real de valor não vazio." Para
`11_transportes` ela erra por um fator de **206×** (5.570 contra 27) e reproduz
exatamente o defeito que diz corrigir. `09_educacao` tem o mesmo mecanismo
(`ano_ref_ideb` é 100% preenchida), embora ali a cobertura substantiva também
seja alta, então o efeito não aparece.

**Tentativa de refutação:** (a) Existe um teste que cobre isto —
`tests/testthat/test-consumo.R:74-82`, "mape_cobertura mede presença de valor,
não presença de linha". Ele passa, mas só exercita `14_corrupcao`, que não tem
coluna `flag_` nem `ano_ref_`; o comentário do próprio teste diz "se a cobertura
desse 100%, a função estaria contando linha em vez de dado" — e é exatamente o
que ela faz em `11_transportes`. O teste dá falsa confiança. (b) Considerei a
leitura de que a flag é um dado legítimo: é — o zero-fill diz "este município não
adotou tarifa zero". Mas então "cobertura" perde o sentido para o qual a função
existe, porque toda dimensão que carregue uma flag preenchida passa a ter 100%
por construção; e a documentação define coberto como ter dado, não como ter
linha. (c) Conferi que não é artefato da minha leitura: `mape_ler_tabela()` não
filtra nada e o cálculo `rowSums(!is.na(...))` é o mesmo da função.

**Correção sugerida:** em `R/consumo.R:312`, excluir do conjunto `dados` as
colunas auxiliares, e reportar as duas medidas:
```r

```
Se a intenção for manter as duas leituras, devolver `cobertura_pct` (substantiva)
e `presenca_pct` (qualquer coluna), em colunas separadas. E trocar o teste de
`14_corrupcao` por `11_transportes`, que é o caso que discrimina.

### A5-04 · ALTO · `mape_deflacionar()` baixa a série de IPCA da API do IPEA a cada chamada — o resultado não é reprodutível nem registrado

**Afirmação:** `mape_deflacionar()` delega a `deflateBR::ipca()`, que chama
`deflateBR::deflate()`, que faz um `httr::GET("http://ipeadata.gov.br/api/odata4/
ValoresSerie(SERCODIGO='PRECOS12_IPCA12')")` **em toda invocação**. A série não é
fixada, não é cacheada, não é versionada em `raw/`, e a deflação não passa por
`mape_registrar_proveniencia()`. Duas execuções em datas diferentes podem gerar
valores diferentes na coluna `*_brl2023`, com o mesmo nome; sem rede, o pipeline
falha.

**Reprodução:**
```r
cat("deflateBR::ipca ->\n"); print(deflateBR::ipca)
cat("\ndeflateBR::deflate ->\n"); print(deflateBR::deflate)

writeLines(readLines("R/deflacao.R")[c(52, 61)])
cat("\nmape_deflacionar e chamada em algum lugar?\n")
arqs <- c(list.files(c("R", "tools", "tests", "fontes"), pattern = "[.]R$",
                     recursive = TRUE, full.names = TRUE), "_targets.R")
usos <- unlist(lapply(setdiff(arqs, "R/deflacao.R"), function(a)
  grep("mape_deflacionar", readLines(a, warn = FALSE), value = TRUE)))
print(usos)
```
